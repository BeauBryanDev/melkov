# Melkov

**Melkov** is a multimodal AI art expert agent built around a fine-tuned **Qwen2.5-VL-7B** vision-language model, retrieval-augmented art-history knowledge, computer vision, and generative image synthesis it used the Claude-Sonnet-5 as Orchestrator Agent from Anthropic API Key. 

Designed as a full-stack AI application, Melkov can analyze artworks, discuss art history and artistic movements, generate original art, search museum collections, and classify artistic styles through a dedicated computer-vision model.

Part of the **Aegis portfolio**, Melkov takes a different direction from the portfolio's detection and classification systems such as Sentinel-Net, Traffic-Sentinel, and DentaVision. It is the portfolio's first **generative, multimodal AI agent focused exclusively on the domain of art**.

Rather than relying on a single model for every task, Melkov uses an orchestrator architecture with **five specialized tools**, each responsible for a specific capability:

1. **Art History RAG** — retrieves relevant knowledge from a curated art-history corpus using ChromaDB and semantic embeddings.
2. **MET Museum Search** — searches the Metropolitan Museum of Art's public collection API and retrieves artwork metadata and museum images.
3. **Artwork Vision & Description** — uses the fine-tuned Melkov VLM to analyze submitted artworks and produce detailed artistic descriptions.
4. **Art Image Generation** — generates original artwork through the FLUX image-generation model served through NVIDIA's API.
5. **Art Style Classification** — uses a custom-trained CNN to classify artworks across 15 artistic styles.

The result is an AI agent that combines **vision, language, retrieval, generation, and computer vision** into a single art-focused system.

Melkov lives in a beautiful web site SPA built with TS/React/Tailwindcss Art-Studio likes.

## 1. What this project is

A user uploads a painting (or any artwork image) and receives an expert
description — style, composition, mood, technique — generated by a
vision-language model fine-tuned specifically on art. Beyond captioning, the
system is designed as a full **agent**: it can answer art-history questions
with retrieval-backed authority, and it can generate new artwork from a text
prompt, refining the request before handing it to an image generation model.

The agent has a name and a persona: **Melkov**, a 21-year-old French art
enthusiast personality layered on top of the fine-tuned model via system
prompting.

## 2. Core models

| Role | Model | Where it lives |
|---|---|---|
| Vision-language orchestrator ("Melkov") | Qwen2-VL-7B-Instruct, QLoRA 4-bit fine-tune | Hugging Face (Inference Endpoint) |
| Image generation | FLUX (open-source) | Hugging Face (Inference Endpoint / Space) |
| Art-history retrieval | ChromaDB vector store over curated art-history documents | Self-hosted alongside the backend (no GPU required) |

Qwen2-VL-7B-Instruct was chosen for consistency with the rest of the Aegis
portfolio (Aegis-CyberSec-Guard fine-tunes the Qwen2.5 family), and because its
instruct-tuned base is well suited to conversational image description.

FLUX was selected as the generative image backbone for its open-source
availability and quality relative to compute cost, hosted independently from
the VLM so the two workloads scale separately.

## 3. Dataset and training

### 3.1 Source

[Trever896/openbrush-75k](https://huggingface.co/datasets/Trever896/openbrush-75k),
a public-domain art dataset (75,313 images, 27 styles, 118 genres, 111
artists), each image paired with an AI-generated structured caption
(subject, action, setting, mood, style, lighting, color, composition).

The full dataset is 254 GB, which does not fit Colab's local disk or a
reasonable Drive budget. A streaming metadata audit was run first
(`audit_openbrush75k.py`) to determine real per-style availability without
downloading the dataset.

### 3.2 Stratified subset

Based on the audit results, a stratified, randomly-sampled subset was
designed via reservoir sampling per style (unbiased, single-pass, no need to
know per-style totals in advance):

- Cap of **1,000 images per style** for the 20 majority styles.
- The 5 minority styles below the cap contribute all their available images
  (Fauvism 870, Pointillism 505, Contemporary 471, New 314, Action 98).
- `Synthetic` (Synthetic Cubism, 119 images) is merged into the `Cubism`
  bucket rather than kept as its own class.
- `Analytical` (Analytical Cubism) is excluded entirely — only 23 images
  exist dataset-wide, insufficient to be a usable class.

Resulting subset: **~22,258 images**, resized to 896x896 (all originals are
larger, so this is pure downsampling, never upscaling), re-encoded as JPEG,
packaged with a `manifest.jsonl` and compressed to `.tar.gz` for transfer to
Google Drive and, from there, to the training session's local disk.

Known data-quality caveat: several style labels in the source dataset are
truncated compound names (e.g. `Art` merges both "Art Nouveau" and "Art
Primitivism" under one categorical label). This affects only the categorical
`style` field used for stratification — the free-text `STYLE` section of each
structured caption remains descriptively accurate and is what the model
actually trains on.

### 3.3 Training configuration

- Method: QLoRA 4-bit fine-tuning (frozen vision encoder; LoRA on the
  projector + LLM, following Unsloth's `FastVisionModel` defaults).
- Hardware: NVIDIA RTX PRO 6000 Blackwell (95 GB VRAM), Colab G4 Expert,
  9 credits/hour.
- Budget: ~120 credits (~13 hours), targeting a 10-hour ceiling per session
  to stay under Colab's 12-hour hard session limit.
- Epochs: 2 (reduced from an initial 3-epoch plan to guarantee completion
  within the credit and session-length budget).

Training infrastructure directly incorporates lessons from the
Aegis-CyberSec-Guard post-mortem (see `Training_Post_Mortem.md`):

- Checkpoints write to local disk (`/content/checkpoints`), never directly
  to a Drive FUSE mount; final artifacts are copied to Drive once at the end.
- A clean benchmark run (no save, no eval) measures real it/s before
  committing to a full run, so the credit budget is computed from a number,
  not a guess.
- Batch size / gradient accumulation is chosen for the configuration with the
  **highest throughput**, not the highest VRAM utilization — near-ceiling
  VRAM triggers gradient offloading in Unsloth, which was empirically slower
  in the prior project despite using more memory.
- Evaluation is subsampled (~300-500 examples) and run infrequently
  (`eval_steps=500`) — a trend indicator, not a full pass every few steps.
- `dataloader_num_workers` tuned to the instance's CPU core count, since
  image decoding is CPU-bound and was previously a hidden bottleneck.
- Since the OpenBrush subset (~22k images at 896x896, a few GB) is far
  smaller than the 254 GB source or the 54 GB dataset from the prior VLM
  training run, it is copied fully to local disk before training — no
  streaming or Drive-backed I/O during the training loop itself.

## 4. Agent architecture

Melkov is designed as an **orchestrator with tools**, not a single
end-to-end responder — the same pattern used in Aegis-CyberSec-Guard
(LogSentinel / NetGuard / VulnLookup as tools) and Aegis-DentaVision
(RAG as a tool).

```
User input (image | question | generation request)
                |
                v
   Melkov (fine-tuned Qwen2-VL-7B + persona system prompt)
                |
        routes to one or more tools
                |
   +------------+-------------+------------------------+
   |                          |                         |
Direct description      Art-history RAG          Image generation
(the fine-tuned VLM      (ChromaDB retrieval       (prompt refined by
 itself, no tool call     over curated art-         Melkov, then sent
 needed)                  history documents)        to FLUX)
```

- **Image uploaded, no specific question** -> Melkov describes it directly
  using its fine-tuned knowledge.
- **Art-history or biographical question** (e.g. "Tell me about Van Gogh's
  turbulent life and how it shaped his masterpieces") -> Melkov calls the
  RAG tool against the ChromaDB art-history store and answers with
  retrieval-backed authority, rather than relying on parametric knowledge
  alone.
- **Generation request** (e.g. "Generate a magical castle in Impressionist
  style") -> Melkov rewrites and constrains the user's prompt to fit FLUX's
  input limits, enriching it with the technical/stylistic vocabulary learned
  during fine-tuning, then calls the FLUX endpoint.
- **Combined requests** (e.g. an uploaded image plus "what inspired this
  style?") -> description and RAG tools can both fire within the same
  response.

This tool-calling separation keeps visual knowledge (fine-tuning) and
historical/biographical knowledge (RAG) independently maintainable — the
RAG corpus can be updated without retraining the model.

## 5. Full-stack architecture

Consistent with the rest of the Aegis portfolio:

| Layer | Technology |
|---|---|
| Backend | Python, FastAPI |
| Image preprocessing | OpenCV |
| Database (RAG) | ChromaDB (self-hosted, no GPU) |
| VLM inference | Qwen2-VL-7B-Instruct (fine-tuned), HF Inference Endpoint |
| Image generation | FLUX, HF Inference Endpoint / Space |
| Frontend | TypeScript, React, Tailwind, Vite |
| Charts (if/when needed) | Recharts |
| Deployment | AWS EC2 (backend + ChromaDB); HF for GPU inference |

The backend hosts the orchestration logic (tool-calling, request routing) and
proxies inference calls to the Hugging Face-hosted models, keeping GPU
inference off the EC2 instance entirely.

A WebSocket connection drives a live "painting in progress" animation on the
frontend while an image generation request is in flight — a UX signature
element analogous to the evidence-linked verdict in Aegis-CyberSec-Guard.

## 6. Visual identity

Departs deliberately from the cyberpunk HUD aesthetic used across most of the
Aegis portfolio (CyberSec-Guard, Sentinel-Net, Scryer). Aegis-Art-Atelier uses
a **Baroque/Rococo European palace** direction — blue and gold, evoking
Versailles, Buckingham Palace, or El Escorial. A gallery/palace feel fits an
art-expert agent far better than a hacker-terminal look.

Planned direction (not yet implemented): deep royal blue as the base surface
color, gold as the accent/ornamental color, an elegant serif face for
Melkov's narrative responses (contrasting with the technical mono/sans split
used in the other Aegis frontends), and restrained ornamental detailing
(corner flourishes, gilded borders) in place of the HUD corner-bracket motif.

## 7. Roadmap

1. Finish dataset ETL (`etl_openbrush75k.py`) — stratified sampling, resize,
   package to Drive.
2. Benchmark cell on the Blackwell GPU to measure real it/s before committing
   the full training run.
3. QLoRA fine-tuning, 2 epochs, following the corrected training
   configuration above.
4. Push the fine-tuned adapter to a Hugging Face Inference Endpoint.
5. Stand up the ChromaDB art-history RAG corpus.
6. Integrate FLUX as the generation tool.
7. Build the FastAPI orchestration layer (tool-calling, routing).
8. Build the React/TS frontend (Baroque/Rococo visual identity).
